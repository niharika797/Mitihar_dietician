PHASE 1 — PLANNED (not started)
================================================================================

Phase 1 builds on the clean Phase 0 foundation. Key features:

1. Patient onboarding flow
   - POST /api/v1/patients/onboarding
   - Calculates + stores BMR, TDEE, BMI on Patient record
   - Accepts full profile (dob, goals, medical conditions etc.)
   - Returns complete profile with calculated values

2. Doctor dashboard
   - GET /api/v1/doctor/patients — list doctor's patients
   - GET /api/v1/doctor/patients/{id}/plan — view patient plan
   - PUT /api/v1/doctor/patients/{id}/plan — edit/override plan
   - POST /api/v1/doctor/subscription-codes — generate codes
   - All routes use request.state.doctor_id from DoctorIsolationMiddleware

3. Patient-Doctor connection flow
   - POST /api/v1/patients/request-doctor — patient sends request
   - POST /api/v1/doctor/requests/{id}/accept|reject
   - Uses PatientRequest table

4. Subscription activation
   - POST /api/v1/patients/activate — patient enters subscription code
   - Validates SubscriptionCode, sets subscription_status="active"
   - Updates JWT sub_status claim on next login

5. Day N+1 calorie adjustment
   - After each logged day, compare actual vs target
   - Redistribute surplus/deficit across next day's meals
   - Uses meal_logs table (already exists)

6. Admin panel (basic)
   - POST /api/v1/admin/doctors — create doctor accounts
   - GET /api/v1/admin/stats — user counts, plan counts

7. Delete models/diet_plan.py
   - Replace with proper Recommendation-based schemas
   - diet_plan_service.py returns Recommendation ORM directly
