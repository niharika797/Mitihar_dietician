# Python Engineering-Quality Audit — `app/` + `scripts/`

**Scope:** `app/` (42 files, 14,265 lines) + `scripts/` (78 files, 13,630 lines, flat, `scripts/archive/` excluded). 120 files, ~27,900 lines. **Method:** static analysis (ruff, mypy) + full manual read of every file across two lenses (general engineering quality; Fluent Python idioms). Read-only — no source modified.

---

## 1. Summary

**Grade: 2.5 / 5** — functional but carrying real, live defects, not just style debt.

The codebase is competently structured at the model/schema layer (SQLAlchemy 2.0 typed style, Pydantic v2, centralized settings) but has accumulated **seven confirmed Critical defects** that are either live crashes on normal user flows, a security gap, or silent data loss — none of them hypothetical, all traced to root cause by reading the actual call sites. The `scripts/` directory (78 one-off maintenance scripts) is the larger risk surface: several DB-mutating scripts have zero dry-run/confirmation gating, five separate files hardcode plaintext DB credentials, and at least one merge script drops patient data silently via an unrepointed foreign key.

**Top 3 risks:**

1. **Two production-request-path crashes are live right now.** `POST /doctor/patients/{id}/weekly-plan/combos/{combo_id}/swap` (`doctor.py:1409`) and `store_diet_plan()` calls from `PATCH /users/me` (`users.py:127`) both raise unconditionally on every invocation — a doctor swap-combo feature and a patient profile-edit diet-plan regeneration are both dead code paths in production today, and the second one fails silently (caught, `print()`ed, 200 OK returned to the client).
2. **A soft-delete/ownership bypass in the weekly-plan dish-swap endpoint** (`doctor.py:1533`) lets a doctor inject a soft-deleted, merged-away, or another doctor's unreviewed dish straight into a patient's live weekly plan — the exact hole `get_assignable_dish()` exists to close, unclosed on this one endpoint.
3. **`app/routers/doctor.py` is a 3,159-line, 47-route, 12-responsibility god-router** carrying real business logic (a 60-dish hardcoded nutrition table, two independent Gemini-calling implementations, duplicated age/total-recalculation math in 3-5 places) that belongs in `app/services/`. Its size and lack of decomposition is why the two Critical bugs above went unnoticed — the swap and patch-dish code paths are ~450 lines apart in the same file and only one of the two got the safety check.

Runtime signal: **ruff found 67 violations across 22 files — all 22 in `scripts/`, zero in `app/`.** **mypy found 158 errors across 15 `app/` files** (mypy is not configured to check `scripts/` at all — every scripts finding below came from manual reading, no tool signal exists there). Most mypy errors are either (a) genuine missing-None-check bugs, (b) a project-wide, CLAUDE.md-documented, accepted `Column[T]`-vs-`T` exemption for the two legacy `FoodItem`/`MealTemplate` classes, or (c) false positives from variable-name reuse defeating narrowing — each is called out individually below with its verdict, not blanket-restated.

## 5. Architecture Notes

- **`app/routers/doctor.py` (3,159 lines, 47 routes) is a god-router** spanning ≥12 unrelated responsibility domains: patient CRUD, onboarding, subscription codes, plan override (v1 JSONB), custom-dish/dish-patch (v1), weekly-plan v2 (WeeklyCombo get/approve/swap/patch), weekly summary, recipe browse/create/assign, recipe tags, two independent Gemini nutrition-estimate implementations plus a hardcoded 60-dish nutrition table, visit/token/renewal flows, per-patient meal-config, and Data Review governance. Recommend splitting into ~10 sub-routers mounted under the same `/doctor` prefix (`doctor_patients.py`, `doctor_plan.py`, `doctor_weekly_plan.py`, `doctor_recipes.py`, `doctor_visits.py`, `doctor_renewals.py`, `doctor_meal_config.py`, `doctor_data_review.py`), with the nutrition-estimation and dish/age/user_data builder logic moved into `app/services/`. Its size is the direct cause of C1/C2 above — the two code paths are ~450 lines apart in the same file and only one got the safety check the other has.
- **`scripts/` (78 flat files) has zero consistent safety-gate convention.** Some scripts (`merge_duplicate_dishes.py`, `derive_medical_tags.py`, `backfill_recipe_ingredients.py`) correctly dry-run by default and require typed confirmation for real writes. Others with equal or greater blast radius (`clean_patients.py`, `apply_evening_fixes.py`, `ai_clean_recipe_names.py`, `clean_dish_names.py`, `fix_recipe_quantities.py`) have no gate at all. This inconsistency — not the absence of *any* pattern — is what makes the ungated scripts dangerous; the safe pattern already exists in the same directory and simply wasn't applied uniformly.
- **`mypy` never runs against `scripts/`** (`pyproject.toml`: `files = ["app"]`). This is a permanent, structural blind spot, not a bug — every type-hint-consistency finding in `scripts/` above came from manual reading, and future scripts will get zero static-analysis signal unless this is revisited.
- **`app/models/db_models.py`'s `FoodItem`/`MealTemplate` DO-NOT-MODIFY exemption is working as documented** — it correctly explains the large mypy `Column[T]` cluster — but the *separate* mutable-shared-default-object bug (18 columns, Major finding above) is real regardless of that exemption; it's a Python/SQLAlchemy semantics issue, not a typing one, and isn't covered by the legacy-style carve-out.
- **`app/schemas/__init__.py` is empty** despite two sibling files independently redefining near-identical bounded-collection helper types — a natural, currently-unused home for shared schema primitives.
- **Duplicated business logic is heavily concentrated in `doctor.py`**: age calculation (3 copies), user_data dict construction (2 copies), dish-dict builders (2 copies in one function), and total-recalculation math (5 copies across 4 endpoints). None of this is duplicated *across* files — it's all within the one god-router — reinforcing the case for decomposition over spot-fixes.
