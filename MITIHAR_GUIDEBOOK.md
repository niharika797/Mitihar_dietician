## 1. Architecture

```
┌─────────────────────────────────────────────────────────┐
│                    MITIHAR SYSTEM                       │
├──────────────────┬──────────────────┬───────────────────┤
│  Patient App     │  Web Dashboard   │  Backend API      │
│  (Expo / RN)     │  (React + Vite)  │  (FastAPI)        │
│  Port: Expo Go   │  Port: 5173      │  Port: 8000       │
│                  │                  │                   │
│  36 screens      │  Doctor + Admin  │  ~84 endpoints    │
│  TanStack Query  │  roles           │  PostgreSQL       │
│  Zustand store   │  Sonner toasts   │  SQLAlchemy 2.0   │
└──────────────────┴──────────────────┴───────────────────┘
```

**Key Design Rules:**
- JWT is claims-only in middleware — no DB calls per request
- Doctor isolation: every query filtered by `doctor_id`
- Tokens: 15-min access JWT + 7-day refresh in HttpOnly cookie

## 7. The Meal Generator — How It Works

This is the core AI engine that builds personalised 7-day Indian diet plans.

### 7.1 Trigger Points

The meal generator runs in three situations:
1. **After onboarding** — auto-generates first plan immediately
2. **Doctor manually triggers** — `PUT /doctor/patients/{id}/plan`
3. **Weekly refresh** — (planned in Phase 5) cron job every Monday

### 7.2 Input Data Used

```python
user_data = {
    "gender":              "Female",
    "height":              162,           # cm
    "weight":              65,            # kg
    "activity_level":      "LA",          # S/LA/MA/VA/SA
    "diet":                "Vegetarian",  # or Non-Vegetarian
    "health_condition":    "Healthy",     # Healthy / Diabetic-Friendly / Gym-Friendly
    "region":              "North",       # North / South / East / West
    "nonveg_meals_per_week": 0,
    "food_allergies":      ["peanuts"],
    "age":                 28,
}
```

### 7.3 Calculation Pipeline

```
Step 1: BMR (Basal Metabolic Rate)
  → Mifflin-St Jeor formula
  → Female: (10 × weight) + (6.25 × height) - (5 × age) - 161
  → Male:   (10 × weight) + (6.25 × height) - (5 × age) + 5

Step 2: TDEE (Total Daily Energy Expenditure)
  → BMR × Activity Multiplier
  → Sedentary (S): × 1.2
  → Lightly Active (LA): × 1.375
  → Moderately Active (MA): × 1.55
  → Very Active (VA): × 1.725
  → Super Active (SA): × 1.9

Step 3: Calorie Target
  → TDEE adjusted by health goal
  → Weight loss: TDEE - 300 kcal
  → Maintenance: TDEE
  → Muscle gain: TDEE + 300 kcal

Step 4: Macro Split
  → Protein: 20-30% of calories
  → Carbohydrates: 45-55% of calories
  → Fat: 20-30% of calories
  → Fiber: 25-38g/day
```

### 7.4 Meal Template System

Templates define the structure of each meal for a given combination of:
- `meal_time`: Breakfast, Morning_Snack, Lunch, Evening_Snack, Dinner
- `region`: North, South, East, West
- `diet_type`: Vegetarian, Non-Vegetarian
- `plan_type`: Healthy, Diabetic-Friendly, Gym-Friendly

Each template specifies slots:
```json
[
  {"slot_type": "grain",    "calorie_pct": 0.35, "required": true},
  {"slot_type": "protein",  "calorie_pct": 0.30, "required": true},
  {"slot_type": "vegetable","calorie_pct": 0.20, "required": false},
  {"slot_type": "dairy",    "calorie_pct": 0.15, "required": false}
]
```

### 7.5 Food Selection Algorithm

For each slot in each meal:
1. Query `food_items` filtered by: `slot_type`, `diet_type`, `region_tags`, `plan_type_tags`
2. Filter out items matching patient's `food_allergies`
3. Pick the item whose `cal_per_serving` is closest to the slot's calorie target
4. Assign it to the meal

### 7.6 Output Plan Format

```json
{
  "week_start_date": "2026-03-10",
  "target_calories": 1650,
  "meals": [
    {
      "Date": "2026-03-10",
      "Meal Type": "Breakfast",
      "Menu Names": "Oats Upma + Moong Dal Cheela",
      "Diet Type": "Vegetarian",
      "Total Calories": 395,
      "Total Protein": 20,
      "Total Carbs": 59,
      "Total Fat": 10,
      "Total Fiber": 6,
      "doctor_note": ""
    }
  ]
}
```

### 7.7 Where Plans Are Stored

Table: `recommendations`
- `patient_id` — which patient
- `is_active` — only one active plan per patient at a time
- `generated_by` — `"system"` or `"doctor"`
- `meals` — JSONB array of 35 meal objects (5 meals × 7 days)
- `week_start_date` — Monday of the plan week
- `doctor_notes` — overall notes from doctor
